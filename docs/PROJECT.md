# VideoCut 项目说明

## 1. 项目概述

VideoCut 是 AI 创作系统中的网页端内容编辑工作台。用户从“全部结果页”或“人工审核页”的某一个素材进入编辑器，对当前素材做必要调整，再导出或覆盖原内容。

它的定位是解决日常、高频、轻量的视频后处理，不是再做一个完整的剪映。第一期优先覆盖用户原来必须下载文件、打开剪映才能完成的操作。

## 2. 背景与目标

### 2.1 背景

用户生成视频后，经常只需要进行简单处理，例如删除不需要的片段、调整速度、补充文字或音频。原流程需要先下载素材，再用剪映编辑，完成后重新上传，步骤多且容易打断审核和交付流程。

### 2.2 目标

- 用户不离开 AI 创作系统即可完成常用编辑。
- 从当前结果进入时，默认只带入被点击的一个素材。
- 需要更多素材时，再通过“添加/导入”主动选择。
- 编辑完成后，可以导出完整视频，或覆盖原内容并回到原业务流程。
- 复用成熟视频编辑器的“预览区 + 工具栏 + 多轨时间轴”操作习惯，同时控制第一期范围。

## 3. 用户使用流程

1. 用户在“全部结果页”或“人工审核页”找到要处理的素材。
2. 点击该素材的“编辑”，进入 VideoCut 工作台。
3. 左侧素材列表默认只显示这一个素材。
4. 点击素材只进行预览；将素材拖入时间轴后才参与编辑。
5. 用户在预览区查看结果，在时间轴中完成分割、移动、变速、倒放、文字等操作。
6. 如需补充素材，点击“导入”，从原料库、系统资源或本地文件中选择。
7. 如需生成新内容，从左侧进入文本生成、图片生成或视频生成，生成完成后选择候选结果加入工作台。
8. 点击“导出”得到完整视频；点击“覆盖”将结果回写为原素材并返回原业务流程。

## 4. 已确认的产品范围

### 4.1 工作台结构

| 区域 | 要求 |
| --- | --- |
| 顶部 | 显示 VideoCut、覆盖、导出 |
| 左侧 | 素材、文字、文本生成、图片生成、视频生成 |
| 中间 | 视频预览；没有素材时仍显示黑色画布 |
| 右侧 | 当前画布或选中片段的属性设置 |
| 底部 | 工具栏、多轨时间轴和播放头 |

不保留项目列表、创建项目或选择工作区的入口。打开网站后直接进入唯一工作台。

### 4.2 素材导入

“导入”列表顺序固定为：

1. 原料库
2. 系统资源
3. 本地文件

当前版本只有“本地文件”可以使用；原料库和系统资源等待业务接口接入。点击素材只预览，拖入时间轴后才添加到作品。

### 4.3 时间轴与编辑

- 支持多个视频轨、音频轨和文字轨。
- 素材进入与自身类型匹配的轨道。
- 片段可以在当前轨道内移动，也可以拖到其他兼容轨道。
- 时间轴不设置固定作品时长，可继续向后编辑。
- 空白位置显示黑色；最终输出截止到最后一个有内容的位置。
- 选中片段后，可以进行分割、删除、变速和倒放等处理。
- 右键片段提供片段级操作，包括变速和只导出当前片段。
- 顶部“导出”导出完整作品。

### 4.4 文字

- 可以新增文字片段。
- 可以编辑文字内容、位置、时长和基础样式。
- 文字作为时间轴内容参与预览和导出。
- 本期需求包含全局文字高亮识别能力；实际识别服务尚未接入。

### 4.5 画布

- 默认使用预设画布尺寸。
- 用户可以在预览区右侧修改宽度、高度和背景。
- 没有视频或图片覆盖的位置显示为黑色。

### 4.6 生成

- 左侧直接提供文本生成、图片生成和视频生成入口，不再先打开一个笼统的“生成面板”。
- 用户填写生成要求并选择参数。
- 生成完成后展示多个候选结果，由用户选择是否加入素材区或时间轴。
- 生成任务不能在公开网页中直接保存 API 密钥，必须由业务服务提供安全接口。

### 4.7 覆盖与导出

| 操作 | 结果 |
| --- | --- |
| 覆盖 | 保存当前编辑结果；接入业务系统后，替换进入编辑器时的原素材 |
| 导出 | 导出时间轴上的完整作品 |
| 右键导出 | 只导出当前选中的片段 |

## 6. 技术边界

VideoCut 当前是纯前端项目：

- 素材导入、时间轴编辑、预览、项目保存和视频导出在浏览器本地完成。
- 项目数据和素材使用浏览器本地存储，不上传到 VideoCut 自有服务器。
- Cloudflare Pages 只负责托管构建后的静态文件。

以下能力需要外部服务：

- AI 文本、图片和视频生成。
- 读取 AI 创作系统的原料库和系统资源。
- 从结果页或审核页传入素材信息。
- 将“覆盖”后的文件和状态回写到原系统。
- 全局文字高亮识别。

## 8. 本地运行

### 8.1 环境要求

- Node.js
- npm
- 最新版 Chrome 或 Edge

### 8.2 启动

```bash
cd /Users/dashan/Desktop/freecut
npm install
npm run dev
```

浏览器打开：

```text
http://127.0.0.1:5173
```

也可以双击桌面的 `启动 VideoCut.command`。

本地启动的是前端开发服务，不是业务后端。使用已经部署的线上地址时，无需启动本地服务。

## 9. Cloudflare Pages 部署

### 9.1 当前部署方式

当前使用 Cloudflare Pages Direct Upload。GitHub 推送不会自动触发线上部署，需要在本地完成构建后手动上传 `dist/`。

### 9.2 部署前检查

```bash
cd /Users/dashan/Desktop/freecut
npm install
npm run check
npm run build
```

检查完成后，确认 `dist/` 已生成。

### 9.3 发布生产版本

```bash
npx wrangler pages deploy dist --project-name videocut --branch develop
```

成功后，Cloudflare 会返回一次部署专属地址；正式体验统一使用：

```text
https://videocut-1du.pages.dev
```

### 9.4 部署后验证

至少检查以下内容：

1. 根地址可以直接进入工作台。
2. `/editor/sucai-edit` 可以直接打开，不出现项目选择或“找不到项目”。
3. 页面显示 VideoCut 品牌、覆盖和导出按钮。
4. 左侧显示素材、文字及三种生成入口。
5. 没有素材时仍能看到黑色预览区和时间轴。
6. 导入本地素材后，可以预览、拖入时间轴并导出。

## 10. GitHub 发布流程

本项目保留两个远程地址：

- `origin`：原始 FreeCut 上游仓库，仅用于获取上游内容。
- `videocut`：VideoCut 的公开 GitHub 仓库，用于正式发布。

当前本地 `develop` 分支跟踪 GitHub 的 `videocut/main`。提交并推送：

```bash
git add <本次修改文件>
git commit -m "说明本次修改"
git push videocut develop:main
```

不要将 VideoCut 修改推送到原始 `origin`。
